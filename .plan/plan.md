# Shape Search 进阶检索实施计划

## 目标与约束

执行调整：用户确认没有真实评测数据，并要求直接实现功能。阶段一以工具链构建、测试和采集支持完成为开发验收；真实草图采集、质量评测、权重校准和失败样本人工分析改为可选后续工作，不再阻塞阶段二及阶段三。功能正确性检查、构建和本机资源检查仍须执行，不声称未经评测的质量提升。阶段四训练需要实际训练/验证数据，不能以实现脚本等同于有效微调模型。

交付范围调整：用户选择先交付阶段一至三的可运行功能，暂不训练。阶段四与可选阶段五留待后续需求，不纳入本次交付。

执行结果：阶段一工具链、阶段二几何检索、阶段三本地 DINOv2 功能均已完成并通过功能验证。分阶段验收记录见 `.plan/phase-1-status.md`、`.plan/phase-2-status.md`、`.plan/phase-3-status.md`。

将当前的“16×16 墨迹密度网格 + 余弦相似度”升级为“视觉特征召回 + 几何精排”，随后根据评测结果引入草图领域对比学习。优先提升真实手绘草图的检索质量，同时保持本地部署和可控资源占用。

- 本地硬件：NVIDIA GeForce RTX 5070 Ti Laptop GPU，显存约 12GB（12227 MiB）。
- 保留现有 React/Vite 前端和七个图标库。
- 图标特征离线计算，在线请求只编码用户草图。
- 模型优先选择 DINOv2 ViT-S/14；SigLIP2 Base/16 作为可选语义分支。
- 显存和延迟必须在本机实测；下文预算不是已验证性能。
- 本计划只安排工作，不代表模型已下载、功能已实现或效果已验证。

## 当前实现

- `src/services/preprocess.ts`：画布像素转换为墨量图。
- `src/services/shapeFeatures.ts`：墨迹裁剪、居中缩放、16×16 密度特征及归一化。
- `src/services/iconSearch.ts`：按库加载索引，全量余弦相似度排序。
- `scripts/buildIconIndex.ts`：离线栅格化 SVG 并生成各库索引。

现有方法可作为对照基线和推理服务不可用时的回退路径。主要短板是对局部结构、线条连接和手绘变形的表达不足。

## 阶段一：建立可复现评测

### 工作

1. 收集 100～300 张真实手绘查询，覆盖不同绘制者、笔画粗细、比例偏差及不完整笔画。
2. 为每张草图标注目标图标和可接受的同义或跨库变体；单独记录严格匹配与可接受匹配。
3. 覆盖难例：放大镜与圆形、文件夹与信封、相似箭头，以及具有不同内部线条的相同外框。
4. 将开发集与最终测试集分离；跨库同形图标分组，避免后续训练与测试泄漏。
5. 建立评测脚本，固定图标库版本、预处理配置和随机种子。

### 记录指标

- Recall@1、Recall@10、Recall@50、Recall@200。
- MRR：首个正确结果的倒数排名均值。
- 查询端到端延迟 P50/P95；模型加载时间单独记录。
- 推理峰值显存、索引大小及内存占用。
- 按草图类型拆分结果，人工检查典型失败案例。

### 验收

现有实现可重复评测，数据标注与分组清晰，后续方案均使用相同测试集进行比较。

## 阶段二：几何检索升级

### 工作

1. 统一 SVG 与草图预处理：保留长宽比、规范留白、固定画布尺寸，处理线宽差异。
2. 增加多尺度密度或边缘特征，兼顾整体布局和局部结构。
3. 为图标预计算轮廓及距离变换；对召回候选计算双向 Chamfer 距离。
4. 限定小幅平移或旋转补偿，避免大范围配准使不同图标变得难以区分。
5. 可选加入骨架端点、交叉点、闭环等拓扑特征；对噪声敏感的特征先通过消融验证。
6. 使用开发集校准几何评分和融合权重；避免直接相加不同量纲的原始分数。

### 验收

对比“原始网格”“多尺度特征”“加入 Chamfer 精排”的质量和延迟。只保留在测试集上产生可解释收益的组件。

## 阶段三：本地视觉模型召回

### 模型选择

| 模型 | 用途 | 初始资源预算 |
| --- | --- | --- |
| DINOv2 ViT-S/14 | 首选视觉编码器，建立深度特征检索基线 | 小批量推理预留约 1～2GB 显存 |
| SigLIP2 Base/16，224 输入 | 可选语义分支，后续支持草图与文字联合检索 | 小批量推理预留约 2～3GB 显存 |

预算仅用于初步规划，实际占用随精度、批量及框架变化。通用视觉模型在极简线稿上可能失效，不能假设替换后必然提升。

### 工作

1. 新增本地 Python 推理服务，绑定本机地址，提供健康检查和草图检索接口。
2. 固定模型版本和预处理参数；查询和图标使用相同编码流程。
3. 优先测试官方全局特征提取方式，再按需要比较其他池化方式。
4. 离线生成归一化图标向量，索引记录模型版本、特征维度、预处理配置和图标 ID。
5. 本地服务加载向量矩阵，用点积执行召回。约 1.6 万图标先使用精确搜索，无需立即引入向量数据库。
6. 从 Top 200 起调节召回数量，使用阶段二几何方法精排。
7. 比较模型单独召回与模型、现有几何特征候选并集，检查正确目标是否在召回阶段丢失。
8. 前端接入异步请求、取消过期请求及错误回退；继续支持图标库过滤和现有结果操作。

### 资源控制

- 从单张查询、较小离线批量和适合硬件的推理精度开始。
- 监测实际峰值显存；发生内存不足时降低批量，不以权重文件大小推断运行占用。
- 在线模型常驻，避免每次搜索重新加载。
- 训练与在线推理分时运行，给系统和其他程序保留显存空间。

### 验收

在本机完成完整图标索引构建和前端查询；显存占用可控。分别报告基线、DINOv2、DINOv2 + 几何精排的质量和延迟。若模型无明显收益，先分析失败模式，再决定是否微调。

## 阶段四：草图领域对比学习

### 数据构建

- 从 SVG 生成线宽变化、轻微抖动、局部形变和少量笔画缺失的草图变体。
- 保留决定图标身份的关键结构；过强增强可能改变语义，需抽样审查。
- 正样本为同一图标的草图与标准图标；跨库等价图标可合并为正样本组。
- 难负样本来自外形相似但目标不同的图标，避免把等价图标误作负样本。
- 使用真实草图验证泛化；合成数据不能替代真实测试集。

### 训练顺序

1. 冻结 DINOv2 编码器，训练小型投影层作为低成本基线。
2. 使用对比学习损失，结合批内负样本与经过检查的难负样本。
3. 若收益不足，解冻最后少量层或评估参数高效微调。
4. 使用混合精度、小批量及梯度累积，并记录峰值显存。
5. 根据开发集选择检查点；最终测试集只用于最终比较。
6. 模型或投影层更新后，重新生成全部图标向量并绑定新的索引版本。

### 验收

微调模型在真实草图测试集上优于未微调模型，难例类别没有明显退化，训练可在本机显存预算内完成。收益不足时保留未微调方案并记录结论。

## 阶段五：按需求扩展语义分支

仅在用户需要“画出概念而非精确轮廓”或文字辅助检索时引入 SigLIP2。

1. 对比图像到图像召回与文字辅助召回。
2. 在开发集校准视觉、语义及几何分数，避免语义相近掩盖外形差异。
3. 保留纯形状检索模式；是否同时常驻两个模型由本机资源评测决定。
4. 质量收益不足时不纳入默认检索流程。

## 建议交付物

- 真实草图评测集、标注说明及数据划分。
- 基线与各阶段方案的评测报告和失败案例。
- 几何特征与精排实现。
- 本地推理服务、依赖锁定和启动说明。
- 深度特征离线索引构建脚本及版本校验。
- 前端模型检索接入、图标库过滤和回退机制。
- 可选的对比学习数据生成、训练配置与模型检查点。

## 实施优先级与决策点

1. 先建立评测基线，明确当前错误来自轮廓偏差还是结构理解。
2. 完成几何升级与 DINOv2 Small 基线，比较单独和组合效果。
3. 选定候选召回和精排策略后，接入本地服务与前端。
4. 当真实草图泛化仍不足时，开展对比学习微调。
5. 有明确语义需求且评测支持时，再加入 SigLIP2。

阶段性目标是取得可复现的质量收益，并明确显存和延迟成本；具体数值门槛在基线完成后确定。
